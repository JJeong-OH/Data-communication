# Data-communication

데이터통신 수업 과제로 작성한 Winsock 소켓 프로그래밍 코드.
TCP/UDP 에코 서버·클라이언트와 UDP 파일 전송 프로그램을 구현했다.

## 개발 환경
- Windows, Visual Studio
- C++ (Winsock2)

## 폴더 구성
```
Data-communication
├── common                  공통 코드
│   ├── Common.h            오류 출력, 시간 측정 함수
│   └── validateIP.h        IP 주소 형식 검사
├── 01_tcp_echo             TCP 에코 서버·클라이언트
├── 02_tcp_multithread      클라이언트마다 스레드를 생성하는 TCP 서버
├── 03_udp_echo             UDP 에코 서버·클라이언트, 응답 보낸 주소 확인
└── 04_udp_file_transfer    UDP 파일 전송
```

## 빌드
Visual Studio의 Developer Command Prompt에서 각 폴더로 이동해 파일마다 따로 빌드한다.
```
cd 04_udp_file_transfer
cl /EHsc UDPFileServer.cpp
cl /EHsc UDPFileClient.cpp
```

## UDP 파일 전송 실행
```
UDPFileServer.exe 9000 받을파일명
UDPFileClient.exe 127.0.0.1 9000 보낼파일명
```

## UDP 파일 전송 방식
1. 클라이언트가 0번 패킷에 파일 크기를 담아 보낸다.
2. 파일을 1024바이트씩 나눠 1번부터 순서 번호를 붙여 보낸다.
3. 서버는 받은 번호로 ACK를 보내고, 클라이언트는 ACK를 받아야 다음 블록을 보낸다.
4. 전송이 끝나면 걸린 시간을 마이크로초 단위로 출력한다.

## 과제 제출 후 개선한 점
처음 제출한 코드에는 아래 문제가 있었고, 이후에 수정했다.

- **패킷 유실 시 무한 대기**
  ACK를 기다리는 시간 제한이 없어서 패킷이 하나라도 유실되면 클라이언트가 멈췄다.
  `SO_RCVTIMEO`로 500ms 타임아웃을 걸고, 시간 안에 ACK가 안 오면 최대 10번까지 다시 보내게 했다.
- **중복 패킷 구분 불가**
  재전송을 넣으면 ACK만 유실된 경우 같은 블록이 두 번 도착해서 파일에 두 번 쓰이게 된다.
  패킷 앞에 4바이트 순서 번호를 붙이고, 서버는 기다리던 번호일 때만 파일에 쓰게 했다.
- **마지막 ACK 유실**
  서버가 마지막 블록을 받자마자 종료하면, 마지막 ACK가 유실됐을 때 클라이언트가 재전송해도 받아줄 곳이 없다.
  서버가 수신을 마친 뒤에도 잠깐 더 대기하면서 재전송된 패킷에 ACK를 보내게 했다.
- **블록 개수 계산 오류**
  `파일크기 / 1024 + 1`로 계산해서, 파일 크기가 1024의 배수거나 0이면 서버가 블록 하나를 더 기다리느라 종료되지 않았다.
  올림 계산(`(파일크기 + 1023) / 1024`)으로 바꿨다.
- **한글 주석 깨짐**
  소스 파일이 CP949로 저장돼 있어서 GitHub에서 한글이 깨져 보였다. UTF-8(BOM)로 변환했다.
